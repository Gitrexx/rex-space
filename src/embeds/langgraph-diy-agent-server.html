LangGraph without the Agent Server

You have Postgres, no Redis and no licence, so the plan is the open-source library plus your own FastAPI layer. Part 1 drills the library calls that layer is made of. Part 2 builds the layer for many pods: runs that outlive a closed tab, streams that resume on any pod, and a Stop button that works from any pod.

The one idea

The Agent Server is the LangGraph library plus a small amount of plumbing that lives between calls and between processes. Inside one process the library already does the hard part: it checkpoints every step to Postgres, resumes from a checkpoint, exposes state, streams what a running graph emits, and pauses for a human. What it has no opinion about is what a fleet of pods must agree on: which runs exist, which pod is executing which one, how a different pod reads that run's output, and how a different pod stops it.

That plumbing is three tables and a doorbell. threads and runs are the registry and the queue. run_events is an append-only log of everything a run emitted. NOTIFY tells the other pods that a table changed, so they don't have to poll hard.

Key insight

Make the HTTP request a reader, never the owner. If the request that starts a run only inserts a row and then reads the run's log the way anyone else would, the three things you asked for stop being features. A closed tab ends a reader, not the run. Reconnecting is a new reader with a cursor. Cancelling is a row update that the owning pod notices.

What Redis is doing in the Agent Server

Less than you might expect. In the deployment docs, Postgres holds every durable thing: assistants, threads, runs, checkpoints, long-term memory and the background queue itself. Redis, in their words, "handles the signaling, cancellation, and streaming pub/sub between API servers and queue workers" and "stores only ephemeral data". So removing Redis does not mean replacing a database. It means replacing a doorbell and a pipe.

What the licence says

The split you ran into is in the package metadata. The library is MIT: langgraph, langgraph-checkpoint-postgres, langgraph-sdk and langgraph-cli. The server (langgraph-api) and the runtime behind langgraph dev (langgraph-runtime-inmem) are published under the Elastic License 2.0.

One correction to "langgraph dev keeps everything in memory": the CLI docs say its state "is persisted to a local directory", so it survives a restart on one machine. It is still a single process with no shared store, described as "suitable for development and testing", which is why it cannot sit behind several pods. langgraph up and the standalone image need Postgres and Redis plus a LangSmith API key for local testing, and the docs state that it "requires a license key for production use".

Before you build: the trade

Building this is a reasonable choice, and it is not free. Weigh it against the alternatives rather than treating it as the default:

  • What you take on. The correctness of a distributed queue, and the long tail the server already has: assistants and versioning, crons, the store API, auth hooks, webhooks, Studio. The reference in this module is about 1,100 lines, passes its tests, and is a subset.
  • Buying the licence is the better answer if you need that long tail or a vendor to call.
  • Aegra is an Apache-2.0 FastAPI + Postgres server that speaks the same protocol. Its current README lists a Redis job queue and pub/sub, so it does not satisfy a no-Redis rule as shipped.
  • Is "no Redis" a hard rule? One small Redis would remove the most delicate part of this design. If the rule is policy, Postgres does the job at the scale most internal agent platforms run at; the capacity section puts numbers and limits on that.
Part 1 · The library

A thread is a key into a log

There is no thread object in LangGraph. A thread is a string you put in config["configurable"]["thread_id"]. Nothing is created until the first checkpoint is written under that key, and nothing else identifies it.

A graph runs in super-steps: every node that is due runs, their writes are merged, and the result is saved as a checkpoint. A checkpoint holds the value of every state key, the nodes that run next, a little metadata and a pointer to its parent. Checkpoint ids sort by creation time, so "the current state of a thread" means the checkpoint with the greatest id.

Everything you will expose over HTTP is a read of that log or an append to it:

CallEffect on the log
ainvoke / astream with inputAppends one checkpoint per super-step
aget_state(config)Reads the newest checkpoint, or the one named by checkpoint_id
aget_state_history(config)Reads all of them, newest first
aupdate_state(config, values)Appends one checkpoint with source="update"
A write addressed to an older checkpointAppends a sibling of its children: a fork

No call edits a checkpoint in place. Step through one thread's life below: a run that pauses for a human, a resume, a manual edit, then a fork from before the approval.

Three keys address the log. thread_id picks the thread. checkpoint_ns is empty for the root graph and "node_name:task_id" for a subgraph's own checkpoints. checkpoint_id names one exact checkpoint, to read it or to write from it.

        
Pending writes. When a super-step runs several nodes in parallel and one of them finishes, its writes are saved at once against the current checkpoint as pending writes. If the step is then interrupted, that node does not run again on resume. You will see this in Stopping a run.

        
An unknown thread is not an error. aget_state on a thread id that was never used returns an empty snapshot: values={}, next=(), created_at=None. Whether that is a 404 is your API's decision, which is one reason your server keeps its own threads table.

Postgres checkpointer setup

      
The checkpointer is the only piece of persistence the library needs, and the Postgres one is the same class the Agent Server uses.


      setup

# pip install "langgraph>=1.2" langgraph-checkpoint-postgres "psycopg[binary,pool]"
from psycopg.rows import dict_row
from psycopg_pool import AsyncConnectionPool
from langgraph.checkpoint.postgres.aio import AsyncPostgresSaver

pool = AsyncConnectionPool(
    "postgresql://app:secret@db:5432/agents",
    min_size=2, max_size=10, open=False,
    kwargs={"autocommit": True, "row_factory": dict_row, "prepare_threshold": 0},
)
await pool.open()

saver = AsyncPostgresSaver(pool)
await saver.setup()                      # once per database: tables and migrations
graph = builder.compile(checkpointer=saver)


      
The three connection options are not decoration:

      
    
        
  • autocommit=True is required. setup() runs CREATE INDEX CONCURRENTLY, which Postgres refuses inside a transaction block, and the saver never commits on a bare connection.
    • 
        
  • row_factory=dict_row is required. The saver reads rows by column name.
    • 
        
  • prepare_threshold=0 is what the library's own from_conn_string sets. Behind PgBouncer in transaction mode, use None so no server-side prepared statements are created.
    • 
      

      
AsyncPostgresSaver.from_conn_string(...) is a context manager around one connection. It suits a script or a test. In a server it would put every checkpoint of every run on a single connection.

      
setup() creates four tables. checkpoints has one row per checkpoint. checkpoint_blobs holds each non-primitive state value, one row per version. checkpoint_writes holds pending writes and interrupt records. checkpoint_migrations tracks schema versions.


      
One saver means one query at a time

      
This is the setting that quietly decides your throughput. AsyncPostgresSaver wraps every database call in a single asyncio.Lock. Handing it a pool does not change that: one saver instance issues one query at a time, whatever the pool size.

Deep dive — hidden in Skim mode

        
What grows. Each time a state key changes, its whole new value is stored as a new row in checkpoint_blobs. An append-only messages list with n turns therefore costs on the order of n² bytes over the life of the thread. Three levers exist. await saver.aprune([thread_id], strategy="keep_latest") keeps only the newest checkpoint per namespace; in a test it took a thread from 5 checkpoints to 1 and kept its state, at the price of history and time travel. await saver.adelete_thread(thread_id) removes everything. DeltaChannel, in beta since 1.2, stores per-step deltas instead of full values, and aprune(keep_latest) refuses threads that use it.

        
Run migrations once, not from every pod. When three pods started together and each called setup() behind pg_advisory_lock(), two of them died with DeadlockDetected. CREATE INDEX CONCURRENTLY waits for every other open transaction, and a session blocked inside pg_advisory_lock() is an open transaction waiting for the index builder. Polling pg_try_advisory_lock() fixed it. A one-off migration job avoids the question.

        
Serialization. State is encoded by JsonPlusSerializer: msgpack with type tags for LangChain and pydantic objects. Pass serde= to the saver to change it. EncryptedSerializer.from_pycryptodome_aes() from langgraph.checkpoint.serde.encrypted encrypts state at rest with the key in LANGGRAPH_AES_KEY.

Three things about aupdate_state surprise people:

      
    
        
  • It is a write, not an assignment. The value goes through the key's reducer, so the list above grew. To replace a reducer-backed value, write Overwrite(value=[…]) from langgraph.types.
    • 
        
  • as_node decides what runs next. The update is recorded as if that node had returned it, so its successors become next. Leave it out and LangGraph picks the node that wrote last.
    • 
        
  • It never rewrites history. It appends a checkpoint whose parent is the one you addressed.
    •

Deep dive — hidden in Skim mode

        
Checkpoint metadata is a free index. Every string, number and boolean in config["metadata"] and config["configurable"] is copied into each checkpoint's metadata, apart from the reserved keys. Run with {"metadata": {"user_id": "u-17"}} and saver.alist(None, filter={"user_id": "u-17"}) finds that user's checkpoints across threads. Part 2 relies on the same mechanism: a run_id in the metadata is how a run finds its own checkpoints again.

        
Why you still want a threads table. alist walks checkpoints, not threads, and a thread has many. A thread also has to exist before its first run, carry a status and an owner, and sort by last activity. None of that belongs in checkpoint rows.

Ask for version="v2"

      
Without it, the shape of each item depends on the arguments: a bare chunk for one mode, (mode, chunk) for a list of modes, (namespace, mode, chunk) once subgraphs=True. With version="v2", available since 1.1, every item is a dict with type, ns and data, and values items also carry interrupts. A server has to serialize whatever comes out, so one shape is worth having.


      
Tokens

      
    
        
  • No .astream() needed. LangGraph attaches a callback to the model, so a plain await llm.ainvoke(…) inside a node streams. On Python 3.10 you must pass the node's config into the model call; from 3.11 it propagates by itself.

Deep dive — hidden in Skim mode

        
astream_events is a different stream. With version="v2" it yields LangChain's callback events: on_chain_start, on_chat_model_stream, on_tool_end and so on. The two-node graph above produced 17 of them. It is finer-grained and noisier; the Agent Server exposes it as stream mode events. interrupt() lets a graph ask a question and wait for the answer, for seconds or for days, without holding a process.

Three places an interrupt shows up

      
    
        
  • In the stream. updates yields {"__interrupt__": (Interrupt, …)}. With version="v2", values items carry part["interrupts"].
    • 
        
  • In the result. ainvoke(…, version="v2") returns a GraphOutput with .value and .interrupts. Without v2 the dict has an "__interrupt__" key.
    • 
        
  • In the state. snap.interrupts is non-empty and snap.next names the paused node.
    • 
      


      
The rule that bites
        
On resume the node runs again from its first line, and this time interrupt() returns the answer. In the test above the node body executed twice for one approval. Anything before the interrupt() call happens twice, so put side effects after it or in the next node.


      
    
        
  • Do not wrap interrupt() in a bare try/except. The pause is delivered as an exception and you would swallow it.
    • 
        
  • Keep the order of interrupt() calls inside a node fixed. Answers are matched by position.
    • 
        
  • Keep the payload JSON-serializable. It goes to a client.
    • 
        
  • Parallel branches can leave several questions pending. Answer them in one call with a map: Command(resume={interrupt_id: value, …}).
    • 
        
  • interrupt_before=[…] and interrupt_after=[…] are static breakpoints for debugging. They pause without a question, and ainvoke(None, config) continues.
    • 
      


      
New input instead of an answer

      
If a thread is waiting on a question and the caller sends ordinary input, LangGraph does not complain. It starts a new turn from START, and the pending question is dropped:

      output

== thread 3 interrupted, next: ('approve',)
after sending fresh input: next: ('approve',) | amount: 2

That is a product decision for your server. Either reject plain input while a thread is interrupted, or treat it as "the user changed the subject".


      

        
Deep dive — hidden in Skim mode

        
Typed answers. Since 1.2.12, interrupt(value, response_schema=Decision) accepts a pydantic model, a TypedDict or a dataclass. Its JSON Schema travels with the interrupt as Interrupt.response_schema, so a client can render a form, and the resume value is validated. A wrong answer raises pydantic.ValidationError and saves nothing, so the question can be answered again.

        
Stale answers. By default an answer to a question nobody is asking is ignored. In strict resume mode the library raises UnknownInterruptError instead, before anything is written. The Agent Server offers this as strict_resume on a run.

      


      

        
A node sends an email and then calls interrupt() for approval. The human approves. How many emails have been sent when the node finally returns?

    • 
          
  • Two.

Resuming re-executes the node from the top, so the send runs again before interrupt() returns the answer. LangGraph checkpoints state; it cannot roll back the outside world. Send after the interrupt(), send from the next node, or make the send idempotent with a key.

The whole design rests on five invariants. Each one is asserted by a test in the reference implementation.

      
    
        
  1. A run executes in a worker task, never in a request. Requests insert rows and read logs.
    2. 
        
  2. At most one run per thread is running. A unique index enforces it, not application code.
    3. 
        
  3. Every event has a gap-free sequence number within its run. A reader is a cursor over that sequence.
    4. 
        
  4. Tables are the truth and NOTIFY only shortens the wait. Every doorbell has a polling fallback.
    5. 
        
  5. A pod writes a run's outcome only while it still owns the run. A pod that lost its lease stays silent.

async def create_run(thread_id: str, body: RunCreate) -> dict:

    modes = [body.stream_mode] if isinstance(body.stream_mode, str) else body.stream_mode
    if unknown := set(modes) - STREAM_MODES:
        raise HTTPException(422, f"unsupported stream_mode {sorted(unknown)}")
    strategy = body.multitask_strategy or "enqueue"  # the Agent Server's default
    kwargs = {
        "input": body.input,
        "command": body.command,
        "config": body.config,
        "stream_mode": modes,
        "stream_subgraphs": body.stream_subgraphs,
        "durability": body.durability,
    }
    to_cancel: list[str] = []
    async with pool.connection() as conn, conn.transaction():
        # Lock the thread row: two concurrent creates on one thread are decided one after
        # the other.
        thread = await (
            await conn.execute(
                "SELECT thread_id FROM threads WHERE thread_id = %s FOR UPDATE",
                (thread_id,),
            )
        ).fetchone()
        if thread is None:
            if body.if_not_exists != "create":
                raise HTTPException(404, f"thread {thread_id} not found")
            await conn.execute("INSERT INTO threads (thread_id) VALUES (%s)", (thread_id,))
        active = await (
            await conn.execute(
                "SELECT run_id FROM runs WHERE thread_id = %s AND status IN "
                "('pending','running')",
                (thread_id,),
            )
        ).fetchall()
        if active and strategy == "reject":
            raise HTTPException(
                409, "thread already has an active run (multitask_strategy=reject)"
            )
        if strategy in ("interrupt", "rollback"):
            to_cancel = [row["run_id"] for row in active]
        run = await (
            await conn.execute(
                """INSERT INTO runs
                     (run_id, thread_id, assistant_id, kwargs, metadata, multitask_strategy)
                   VALUES (%s, %s, %s, %s, %s, %s) RETURNING *""",
                (
                    str(uuid.uuid4()),
                    thread_id,
                    body.assistant_id,
                    Jsonb(jsonable(kwargs)),
                    Jsonb(body.metadata or {}),
                    strategy,
                ),
            )
        ).fetchone()
        await conn.execute(
            "UPDATE threads SET status = 'busy', updated_at = now(), metadata = metadata "
            "|| %s WHERE thread_id = %s",
            (Jsonb({"graph_id": body.assistant_id}), thread_id),
        )
    for run_id in to_cancel:  # the new run starts when the old one has stopped
        await request_cancel(run_id, strategy)
    await notify("run_queue")  # after commit: wake the workers on every pod
    hub.queue_bell.set()
    return run

WITH claimed AS (
  UPDATE runs r SET status = 'running', worker_id = %(worker)s, attempt = r.attempt + 1,

Lease, heartbeat, sweeper

      
Claiming sets lease_until a few seconds ahead. One loop per pod keeps that promise alive, and the same loop takes over runs whose owner stopped keeping it.

async def heartbeat_loop() -> None:
    tick = 0
    while True:
        await asyncio.sleep(HEARTBEAT_S)
        tick += 1
        try:
            # renew the leases of runs that are alive HERE, and read their cancel flags
            mine = await fetchall(
                """UPDATE runs SET lease_until = now() + %s * interval '1 second'
                   WHERE worker_id = %s AND status = 'running' AND run_id = ANY(%s)
                   RETURNING run_id, cancel_requested""",
                (LEASE_S, WORKER_ID, list(local)),
            )
            for row in mine:
                if row["cancel_requested"]:  # the doorbell was missed: the row is the truth
                    cancel_local(row["run_id"], row["cancel_requested"])
            for run_id in set(local) - {row["run_id"] for row in mine}:
                me = local[run_id]
                if (
                    me.task and not me.task.done()
                ):  # we no longer own it: stop and stay silent
                    me.fenced = True
                    me.task.cancel()
            expired = (
                await fetchall(  # any pod may take over runs whose owner stopped renewing
                    """UPDATE runs
                       SET worker_id = NULL, lease_until = NULL, updated_at = now(),
                         status = CASE WHEN attempt >= %s THEN 'error' ELSE 'pending' END,
                         error = CASE WHEN attempt >= %s THEN 'worker lost' ELSE error END
                       WHERE status = 'running' AND lease_until < now()
                       RETURNING run_id, thread_id, assistant_id, status""",
                    (MAX_ATTEMPTS, MAX_ATTEMPTS),
                )
            )
            for row in expired:
                if row["status"] == "error":  # crashed its worker too often: stop retrying
                    await fetchall(
                        "UPDATE threads SET status = 'error', updated_at = now() WHERE "
                        "thread_id = %s RETURNING 1",
                        (row["thread_id"],),
                    )
                    await close_unowned(row["run_id"], "error")
            if expired:
                await notify("run_queue")
            if tick % 60 == 0:  # the log is for replay, not for history
                await fetchall(
                    """DELETE FROM run_events e USING runs r
                       WHERE e.run_id = r.run_id AND r.status NOT IN ('pending','running')
                         AND r.updated_at < now() - %s * interval '1 second' RETURNING 1""",
                    (EVENT_TTL_S,),
                )
        except Exception:
            log.exception("heartbeat failed")


      
    
        
  • It renews only runs that are alive in this process. If a run row says "mine" but no local task exists, the lease is allowed to lapse so another pod recovers it.
    • 
        
  • The same query returns cancel flags. A missed cancel doorbell is caught here. Measured: 1.1 to 1.9 s with a 2 s heartbeat.
    • 
        
  • A local run missing from the result has been taken over. The pod marks it fenced and cancels it. A fenced run writes nothing more.
    • 
        
  • Any pod may sweep. Expired runs go back to pending. A run that has already been attempted MAX_ATTEMPTS times is failed instead, so one poisonous input cannot crash pods forever.
    • 
      


      

        
The claim query already checks NOT EXISTS (… status = 'running') for the thread. Why is the unique index still needed?

        
    
          
  • It is not. It only makes the subquery faster.
    • 
          
  • Two pods can claim two different pending runs of one thread at the same moment, and neither sees the other's uncommitted row.
    • 
          
  • SKIP LOCKED sometimes hands the same row to two workers.
    • 
        

        
SKIP LOCKED never hands out a row twice. The gap is across rows: each pod's NOT EXISTS reads a snapshot taken before the other committed, so both conclude the thread is free. The index makes the second commit fail, and the worker picks again. With twelve runs enqueued on one thread through three pods, a sampler never saw more than one running.

def to_event(part: dict) -> tuple[str, Any]:
    kind, data = part["type"], part["data"]
    if kind == "values" and part.get("interrupts"):
        data = {**data, "__interrupt__": part["interrupts"]}
    return "|".join((kind, *part["ns"])), data  # subgraph events: "updates|child:<task_id>"


def graph_for(assistant_id: str):
    # A saver per run/request: one AsyncPostgresSaver serializes all its DB calls behind an
    # internal lock, so sharing a single instance would cap the pod at one query at a time.
    return GRAPHS[assistant_id].copy(update={"checkpointer": AsyncPostgresSaver(pool)})


async def execute(run: dict) -> None:
    run_id, thread_id, kw = run["run_id"], run["thread_id"], run["kwargs"]
    me = local[run_id]
    try:
        graph = graph_for(run["assistant_id"])
        user = kw.get("config") or {}
        config = {
            **user,
            "configurable": {**user.get("configurable", {}), "thread_id": thread_id},
            # The SAME run_id on every attempt: LangGraph sees that the thread's last
            # checkpoint belongs to this run and resumes from it instead of applying the
            # input again.
            "metadata": {**user.get("metadata", {}), "run_id": run_id},
        }
        graph_input = Command(**kw["command"]) if kw.get("command") else kw.get("input")
        modes = ["messages" if m == "messages-tuple" else m for m in kw["stream_mode"]]
        last = await fetchone(
            "SELECT coalesce(max(seq), 0) AS seq FROM run_events WHERE run_id = %s",
            (run_id,),
        )
        events.seq[run_id] = last["seq"]  # continue numbering after an earlier attempt
        events.append(run_id, "metadata", {"run_id": run_id, "attempt": run["attempt"]})

        async def drive() -> None:
            async for part in graph.astream(
                graph_input,
                config,
                stream_mode=modes,
                subgraphs=bool(kw.get("stream_subgraphs")),
                durability=kw.get("durability"),
                control=me.control,
                version="v2",
            ):
                events.append(run_id, *to_event(part))

        me.task = asyncio.create_task(drive())
        if draining.is_set():
            me.control.request_drain("shutdown")
        await asyncio.wait({me.task})  # never raises; we read the outcome ourselves
        error: BaseException | None = None
        try:
            me.task.result()
            outcome = "finished"
        except asyncio.CancelledError:
            outcome = "cancelled"
        except GraphDrained:
            outcome = "drained"
        except Exception as exc:  # noqa: BLE001 - a failing graph is data, not a crash
            outcome, error = "failed", exc

        if me.fenced:  # another pod owns this run now
            events.discard(run_id)
            return
        if outcome == "drained" or (outcome == "cancelled" and me.cancel_action is None):
            await events.flush()  # shutdown: hand the run back to the queue
            await fetchall(
                """UPDATE runs SET status = 'pending', worker_id = NULL, lease_until = NULL,
                          updated_at = now()
                   WHERE run_id = %s AND worker_id = %s AND status = 'running'
                   RETURNING 1""",
                (run_id, WORKER_ID),
            )
            await notify("run_queue")
            return
        if outcome == "failed":
            status = "error"
            events.append(
                run_id, "error", {"error": type(error).__name__, "message": str(error)}
            )
        elif outcome == "cancelled":
            status = "interrupted"
            if me.cancel_action == "rollback":
                await rollback_checkpoints(thread_id, run_id)
        else:  # finished: done, or paused at an interrupt()
            status = "interrupted" if (await graph.aget_state(config)).next else "success"
        # Order matters: (1) every event is in the log, (2) the rows flip, (3) 'end' is
        # appended. A client that sees 'end' and immediately reads the thread finds its
        # final status.
        await events.flush()
        if await finish(run, status, str(error) if error else None):
            events.append(run_id, "end", {"run_id": run_id, "status": status})
            await events.flush()
    except Exception:
        log.exception(
            "run %s crashed in the executor; the lease will expire and it is retried",
            run_id,
        )
    finally:
        local.pop(run_id, None)
        events.seq.pop(run_id, None)
        hub.queue_bell.set()  # capacity freed: look at the queue again

  • The same run_id on every attempt. This is the rule from Part 1. A retry re-sends the stored input, and LangGraph resumes instead of applying it twice.

  • Events, then rows, then end. When a client sees end, the thread's final status is already readable. The first version of this code appended end before updating the rows, and a test that read the thread right after end caught the thread still marked busy.

class EventLog:
    """Pod-wide batcher: every FLUSH_S one INSERT for all runs, then one NOTIFY."""

    def __init__(self) -> None:
        self.buf: list[tuple[str, int, str, str]] = []
        self.seq: dict[str, int] = {}
        self.lock = asyncio.Lock()  # flushes commit in order -> seq is a safe cursor

    def append(self, run_id: str, event: str, data: Any) -> None:
        self.seq[run_id] = seq = self.seq[run_id] + 1
        self.buf.append(
            (run_id, seq, event, data if isinstance(data, str) else dumps(data))
        )

    def discard(self, run_id: str) -> None:
        self.buf = [row for row in self.buf if row[0] != run_id]
        self.seq.pop(run_id, None)

    async def flush(self) -> None:
        async with self.lock:
            rows, self.buf = self.buf, []
            if not rows:
                return
            try:
                run_ids, seqs, names, datas = (list(col) for col in zip(*rows, strict=True))
                await fetchall(
                    """INSERT INTO run_events (run_id, seq, event, data)
                    SELECT * FROM unnest(%s::text[], %s::bigint[], %s::text[], %s::text[])
                    ON CONFLICT DO NOTHING RETURNING 1""",
                    (run_ids, seqs, names, datas),
                )
            except Exception:
                self.buf[:0] = rows  # keep them for the next tick
                raise
            distinct = sorted(set(run_ids))  # committed first, doorbell second
            for i in range(
                0, len(distinct), 150
            ):  # NOTIFY payloads are capped at 8000 bytes
                await notify("run_events", ",".join(distinct[i : i + 150]))

    async def run(self) -> None:
        while True:

class Hub:
    """One LISTEN connection per pod, fanned out to the coroutines waiting here."""

    def __init__(self) -> None:
        self.waiters: defaultdict[str, set[asyncio.Event]] = defaultdict(set)
        self.queue_bell = asyncio.Event()  # "a run may be claimable"

    @contextlib.contextmanager
    def subscribe(self, run_id: str):
        bell = asyncio.Event()
        self.waiters[run_id].add(bell)
        try:
            yield bell
        finally:
            self.waiters[run_id].discard(bell)
            if not self.waiters[run_id]:
                del self.waiters[run_id]

    def ring_all(self) -> None:
        for bells in self.waiters.values():
            for bell in bells:
                bell.set()
        self.queue_bell.set()

    async def run(self) -> None:
        while True:
            try:
                # LISTEN is session state: it needs a real connection of its own
                # (never one from a PgBouncer transaction pool).
                async with await AsyncConnection.connect(DSN, autocommit=True) as conn:
                    for channel in ("run_events", "run_cancel", "run_queue"):
                        await conn.execute(f"LISTEN {channel}")
                    self.ring_all()  # anything sent while we were deaf: re-read
                    async for n in conn.notifies():
                        if n.channel == "run_events":
                            for run_id in n.payload.split(","):
                                for bell in self.waiters.get(run_id, ()):
                                    bell.set()
                        elif n.channel == "run_cancel":
                            action, _, run_id = n.payload.partition(":")
                            cancel_local(run_id, action)
                        else:
                            self.queue_bell.set()
            except asyncio.CancelledError:
                raise
            except Exception:
                log.exception("listener lost; reconnecting")
                await asyncio.sleep(1)

async def tail(run_id: str, after: int = 0):
    """Yield a run's events with seq > after: replay what exists, then follow live."""
    with hub.subscribe(run_id) as bell:  # subscribe BEFORE the first read
        over = False
        while True:
            bell.clear()  # clear, then read: no lost wake-up
            rows = await fetchall(
                "SELECT seq, event, data FROM run_events WHERE run_id = %s AND seq > %s "
                "ORDER BY seq LIMIT 500",
                (run_id, after),
            )
            for row in rows:
                after = row["seq"]
                yield row
                if row["event"] == "end":
                    return
            if len(rows) == 500:
                continue  # still replaying a long log
            if draining.is_set():
                return  # this pod is going away: the client reconnects elsewhere
            if not rows:
                if over:  # finished, and the log has nothing more: close the stream
                    yield {
                        "seq": after + 1,
                        "event": "end",
                        "data": dumps({"run_id": run_id, "status": over}),
                    }
                    return
                run = await fetchone("SELECT status FROM runs WHERE run_id = %s", (run_id,))
                if run is None or run["status"] not in ("pending", "running"):
                    over = run["status"] if run else "deleted"
                    continue  # read once more: events are flushed before the status flips
            try:
                await asyncio.wait_for(bell.wait(), PING_S)
            except asyncio.TimeoutError:
                yield None  # keep-alive tick; the loop re-reads the table


def sse(row: dict | None) -> str:
    if row is None:
        return ": ping\n\n"
    return f"id: {row['seq']}\nevent: {row['event']}\ndata: {row['data']}\n\n"

Deep dive — hidden in Skim mode

        
Why seq > last never skips a row. A cursor is only safe if rows become visible in cursor order. Here each run has one writer, and that writer's flushes are serialized, so batch 2 cannot commit before batch 1. Compare a shared bigserial across many writers: ids are handed out when a row is inserted, not when it commits. Writer A takes id 7 and commits late; a reader sees 8, moves its cursor to 8, and never returns for 7. Per-run sequences with a single writer avoid the whole class of bug.

        
The primary key is also a fence. If a pod that lost its lease is still alive and flushes stale events, ON CONFLICT DO NOTHING drops whatever the new owner has already written. The event log is display data. The checkpoint stays the source of truth either way.

        
Fewer rows. The reference stores one row per event. If volume becomes a concern, merge consecutive token chunks of the same message inside each 50 ms window before inserting them. Clients cannot tell the difference, because they concatenate by message id anyway.

      


      

        
Why not put the token itself in the NOTIFY payload and skip the table?

        
    
          
  • Payloads are limited to 8000 bytes, which is too small for a token.
    • 
          
  • A notification reaches only sessions listening at that instant, so a client that was away could never catch up.
    • 
          
  • NOTIFY cannot be sent from an async driver.
    • 
        

        
A token fits easily in 8000 bytes. The problem is that pub/sub has no memory: nothing is kept for a tab that was closed, a pod that was restarting, or a listener that was reconnecting. Your two requirements, "the run continues without me" and "I can pick the stream up again", both need the events to exist somewhere after they were sent. Once they are in a table, the notification only needs to say that the table changed.

async def request_cancel(run_id: str, action: str = "interrupt") -> dict | None:
    run = await fetchone(  # one atomic statement decides the race against a worker's claim
        """UPDATE runs SET cancel_requested = %s, updated_at = now(),
                  status = CASE WHEN status = 'pending' THEN 'interrupted' ELSE status END
           WHERE run_id = %s AND status IN ('pending','running') RETURNING *""",
        (action, run_id),
    )
    if run is None:
        return None  # already finished
    if (
        run["status"] == "interrupted"
    ):  # it never started: nobody else will close its stream
        status = await thread_status(run["thread_id"], run["assistant_id"])
        await fetchall(
            "UPDATE threads SET status = %s, updated_at = now() WHERE thread_id = %s "
            "RETURNING 1",
            (status, run["thread_id"]),
        )
        await close_unowned(run_id, "interrupted")
    else:
        await notify(
            "run_cancel", f"{action}:{run_id}"
        )  # every pod hears it; the owner acts
    return run

def cancel_local(run_id: str, action: str = "interrupt") -> None:
    me = local.get(run_id)

        me.cancel_action = action
        me.task.cancel()  # CancelledError lands inside the running node

  4. If the bell was lost, the heartbeat finds the flag. The owner reads cancel_requested with every lease renewal.

def begin_drain() -> None:
    """SIGTERM: stop claiming, end SSE responses, let runs stop at the next super-step."""
    draining.set()
    hub.ring_all()
    for me in local.values():
        me.control.request_drain("shutdown")


@asynccontextmanager
async def lifespan(app: FastAPI):
    global pool
    pool = AsyncConnectionPool(
        DSN,
        min_size=2,
        max_size=int(os.environ.get("POOL_MAX", "10")),
        open=False,
        kwargs=CONN_KW,
    )
    await pool.open()
    async with (
        pool.connection() as conn
    ):  # in production: a migration job, not pod start-up
        # One pod migrates at a time. Poll with try-lock instead of blocking in
        # pg_advisory_lock(): setup() runs CREATE INDEX CONCURRENTLY, which waits for every
        # open transaction, including a session that is blocked waiting for this very lock.
        # That is a deadlock.
        while not (
            await (
                await conn.execute("SELECT pg_try_advisory_lock(727274) AS ok")
            ).fetchone()
        )["ok"]:
            await asyncio.sleep(0.2)
        try:
            await AsyncPostgresSaver(conn).setup()  # LangGraph's own tables + migrations
            for statement in SCHEMA:
                await conn.execute(statement)
        finally:
            await conn.execute("SELECT pg_advisory_unlock(727274)")
    background = [
        asyncio.create_task(job())
        for job in (hub.run, events.run, worker_loop, heartbeat_loop)
    ]

    loop = asyncio.get_running_loop()
    previous = signal.getsignal(signal.SIGTERM)  # uvicorn's handler

    def on_sigterm(signum, frame):
        loop.call_soon_threadsafe(begin_drain)  # ours first ...
        if callable(previous):
            previous(signum, frame)  # ... then uvicorn starts its own shutdown

    signal.signal(signal.SIGTERM, on_sigterm)
    yield
    begin_drain()
    tasks = [me.task for me in local.values() if me.task]
    if tasks:  # give the current super-steps time to finish
        _, late = await asyncio.wait(tasks, timeout=GRACE_S)
        for task in late:
            task.cancel()  # too slow: cancel; execute() re-queues it
    for _ in range(100):  # let execute() write its final rows
        if not local:
            break
        await asyncio.sleep(0.05)
    await events.flush()
    for task in background:
        task.cancel()
    await pool.close()

Deep dive — hidden in Skim mode

        
Why hook the signal instead of using lifespan shutdown alone. uvicorn waits for open connections to close before it runs the lifespan's shutdown half. An SSE response never closes by itself, so a pod with streams would sit there until Kubernetes kills it. Chaining the handler lets the streams end first. This was tested on uvicorn 0.54; a preStop hook calling an internal drain endpoint is an alternative that does not touch signals.

        
Kubernetes settings that go with it. Set terminationGracePeriodSeconds above GRACE_S plus a margin. Make the readiness probe fail while draining so the Service stops sending new requests; the reference's /ok reports draining but still answers 200. Give proxies an idle timeout above PING_S, and turn response buffering off for the stream routes.

        
Attempts are counted, not classified. A graceful hand-back also increments attempt. Only the sweeper enforces MAX_ATTEMPTS, and only when a lease expires, so drains alone never fail a run. A run that was handed over three times and then crashes is failed instead of retried. Keep a separate crash counter if that matters to you.

      


      

        
During a rolling deploy, why does the server call request_drain() on each run instead of cancelling its task?

    • 
          
  • A drain stops on a super-step boundary, so the next pod re-executes nothing.
    • 
          
  • Cancelled tasks cannot be re-queued.

Both paths keep the checkpoints and both end with the run back in the queue. The difference is where the thread stops. A cancel lands inside a node, and that node must run again on the next pod. INSERT, then NOTIFY as its own statement        4964 /s   (two round trips per iteration)
NOTIFY only (no row written)                   10771 /s


      
Recall.ai traced production outages to this lock in 2025. DBOS showed in 2026 that buffering notifications and sending them in batches sidesteps it, reaching 60,000 writes a second in their test. The two disagree on whether a recent change in Postgres core removes the bottleneck. This design does not need to know who is right:

      
    
        
  • NOTIFY never shares a transaction with a write. It is always its own statement, sent after the commit.
    • 
        
  • Each pod sends about 20 notifications a second for events, whatever the token rate, because the flusher batches all its runs.
    • 
        
  • No notification carries data. Losing one costs latency and nothing else.
    • 
      


      
Budget

      
    
        
  • Connections. Each pod holds its pool, 10 by default, plus one listener. Ten pods need 110 connections, and Postgres defaults to max_connections = 100. Raise it, shrink the pools, or put PgBouncer in front of them with prepare_threshold=None. The listener must connect directly: LISTEN is session state, and transaction pooling discards it.
    • 
        
  • Rows. A 1,000-token answer is about 1,000 rows in run_events. The heartbeat loop deletes a run's events an hour after it ends. Check that autovacuum keeps up with that churn, or partition the table by day and drop partitions.
    • 
        
  • The event loop. One pod is one event loop for graphs, readers, the flusher and the heartbeat. Blocking it stalls every stream on the pod. Block it for longer than the lease and another pod takes the run over while the first still executes it.
    • 
      


      measured: a node that sleeps 0.5 s with time.sleep()

sync node  (def)       + time.sleep(0.5): event loop stalled for at most 1 ms
async node (async def) + time.sleep(0.5): event loop stalled for at most 490 ms

      
LangGraph runs plain def nodes in a thread, so blocking code is safe there. Inside an async def node the same call freezes the pod. Use async clients in async nodes, and move CPU-heavy work to asyncio.to_thread or another process.

When to add Redis after all
        
Thousands of concurrent streams, a token-latency budget under about 10 ms, run_events dominating your write-ahead log, or lock waits on NOTIFY showing up in pg_stat_activity. At that point replace the transport of the event log and keep everything else. The queue, the lease, the cancel flag and the reader's cursor logic do not change.

    



    


    

      Wrap-up
      
Where people go wrong


      
In the library
        
    
          
  • One shared AsyncPostgresSaver. It runs one query at a time, whatever the pool size. Give each run its own saver on the shared pool.
    • 
          
  • Retrying with a fresh run id. The same input under a new run_id is a new turn: the message is applied twice. A retry must reuse the id.
    • 
          
  • Side effects in a node that can run twice. A resume after interrupt(), a crash recovery and a Continue after Stop all re-execute a node from its first line.
    • 
          
  • durability="exit" on long runs. Nothing is saved until the call returns. A killed pod loses the run.
    • 
          
  • Missing tokens from subgraphs. Without subgraphs=True, LLM calls inside a subgraph stream nothing.
    • 
        


      
In the queue
        
    
          
  • Running the graph inside the request handler. It works with one pod and one patient tab. Then a tab closes and takes the run with it, or a reconnect reaches a pod that has never heard of the run.
    • 
          
  • Enforcing "one run per thread" in code. Two pods read the same snapshot and both proceed. Only a constraint in the database sees both.
    • 
          
  • Calling setup() from every pod at start-up. CREATE INDEX CONCURRENTLY deadlocked against pods waiting for the migration lock. Migrate once, from a job.
    • 
          
  • Blocking the event loop. A time.sleep or a sync HTTP client in an async def node froze the loop for 490 ms in the test. Freeze it past the lease and the run executes on two pods.
    • 
          
  • Enqueueing unvalidated input. A value that breaks a reducer is saved before it fails, and afterwards even reading the thread raises.
    • 
        


      
In the stream
        
    
          
  • Treating NOTIFY as the transport. It has no memory. Put the data in a table and let the notification say that the table changed.
    • 
          
  • NOTIFY inside the writing transaction. Commits that notify go one at a time, across the whole database.
    • 
          
  • LISTEN through PgBouncer in transaction mode. The subscription vanishes with the transaction. The listener needs a direct connection.
    • 
          
  • Reading before subscribing, or waiting without a timeout. The first loses wake-ups. The second turns one lost wake-up into a hung stream.
    • 
          
  • Forgetting the proxies. Response buffering holds tokens back, and idle timeouts cut quiet streams. Disable buffering on stream routes and send keep-alives.
    • 
          
  • Ignoring attempt in the client. After a takeover, the interrupted node's output arrives again. Drop the partial message when the attempt number rises.
    •

class Hub:
    """One LISTEN connection per pod, fanned out to the coroutines waiting here."""

    def __init__(self) -> None:
        self.waiters: defaultdict[str, set[asyncio.Event]] = defaultdict(set)
        self.queue_bell = asyncio.Event()  # "a run may be claimable"

    @contextlib.contextmanager
    def subscribe(self, run_id: str):
        bell = asyncio.Event()
        self.waiters[run_id].add(bell)
        try:
            yield bell
        finally:
            self.waiters[run_id].discard(bell)
            if not self.waiters[run_id]:
                del self.waiters[run_id]

    def ring_all(self) -> None:
        for bells in self.waiters.values():
            for bell in bells:
                bell.set()
        self.queue_bell.set()

    async def run(self) -> None:
        while True:
            try:
                # LISTEN is session state: it needs a real connection of its own
                # (never one from a PgBouncer transaction pool).
                async with await AsyncConnection.connect(DSN, autocommit=True) as conn:
                    for channel in ("run_events", "run_cancel", "run_queue"):
                        await conn.execute(f"LISTEN {channel}")
                    self.ring_all()  # anything sent while we were deaf: re-read
                    async for n in conn.notifies():
                        if n.channel == "run_events":
                            for run_id in n.payload.split(","):
                                for bell in self.waiters.get(run_id, ()):
                                    bell.set()
                        elif n.channel == "run_cancel":
                            action, _, run_id = n.payload.partition(":")
                            cancel_local(run_id, action)
                        else:
                            self.queue_bell.set()
            except asyncio.CancelledError:
                raise
            except Exception:
                log.exception("listener lost; reconnecting")
                await asyncio.sleep(1)

class EventLog:
    """Pod-wide batcher: every FLUSH_S one INSERT for all runs, then one NOTIFY."""

    def __init__(self) -> None:
        self.buf: list[tuple[str, int, str, str]] = []
        self.seq: dict[str, int] = {}
        self.lock = asyncio.Lock()  # flushes commit in order -> seq is a safe cursor

    def append(self, run_id: str, event: str, data: Any) -> None:
        self.seq[run_id] = seq = self.seq[run_id] + 1
        self.buf.append(
            (run_id, seq, event, data if isinstance(data, str) else dumps(data))
        )

    def discard(self, run_id: str) -> None:
        self.buf = [row for row in self.buf if row[0] != run_id]
        self.seq.pop(run_id, None)

    async def flush(self) -> None:
        async with self.lock:
            rows, self.buf = self.buf, []
            if not rows:
                return
            try:
                run_ids, seqs, names, datas = (list(col) for col in zip(*rows, strict=True))
                await fetchall(
                    """INSERT INTO run_events (run_id, seq, event, data)
                    SELECT * FROM unnest(%s::text[], %s::bigint[], %s::text[], %s::text[])
                    ON CONFLICT DO NOTHING RETURNING 1""",
                    (run_ids, seqs, names, datas),
                )
            except Exception:
                self.buf[:0] = rows  # keep them for the next tick
                raise
            distinct = sorted(set(run_ids))  # committed first, doorbell second
            for i in range(
                0, len(distinct), 150
            ):  # NOTIFY payloads are capped at 8000 bytes
                await notify("run_events", ",".join(distinct[i : i + 150]))

    async def run(self) -> None:
        while True:
            await asyncio.sleep(FLUSH_S)
            try:
                await self.flush()
            except Exception:
                log.exception("event flush failed; will retry")

async def tail(run_id: str, after: int = 0):
    """Yield a run's events with seq > after: replay what exists, then follow live."""
    with hub.subscribe(run_id) as bell:  # subscribe BEFORE the first read
        over = False
        while True:
            bell.clear()  # clear, then read: no lost wake-up
            rows = await fetchall(
                "SELECT seq, event, data FROM run_events WHERE run_id = %s AND seq > %s "
                "ORDER BY seq LIMIT 500",
                (run_id, after),
            )
            for row in rows:
                after = row["seq"]
                yield row
                if row["event"] == "end":
                    return
            if len(rows) == 500:
                continue  # still replaying a long log
            if draining.is_set():
                return  # this pod is going away: the client reconnects elsewhere
            if not rows:
                if over:  # finished, and the log has nothing more: close the stream
                    yield {
                        "seq": after + 1,
                        "event": "end",
                        "data": dumps({"run_id": run_id, "status": over}),
                    }
                    return
                run = await fetchone("SELECT status FROM runs WHERE run_id = %s", (run_id,))
                if run is None or run["status"] not in ("pending", "running"):
                    over = run["status"] if run else "deleted"
                    continue  # read once more: events are flushed before the status flips
            try:
                await asyncio.wait_for(bell.wait(), PING_S)
            except asyncio.TimeoutError:
                yield None  # keep-alive tick; the loop re-reads the table

async def execute(run: dict) -> None:
    run_id, thread_id, kw = run["run_id"], run["thread_id"], run["kwargs"]
    me = local[run_id]
    try:
        graph = graph_for(run["assistant_id"])
        user = kw.get("config") or {}
        config = {
            **user,
            "configurable": {**user.get("configurable", {}), "thread_id": thread_id},
            # The SAME run_id on every attempt: LangGraph sees that the thread's last
            # checkpoint belongs to this run and resumes from it instead of applying the
            # input again.
            "metadata": {**user.get("metadata", {}), "run_id": run_id},
        }
        graph_input = Command(**kw["command"]) if kw.get("command") else kw.get("input")
        modes = ["messages" if m == "messages-tuple" else m for m in kw["stream_mode"]]
        last = await fetchone(
            "SELECT coalesce(max(seq), 0) AS seq FROM run_events WHERE run_id = %s",
            (run_id,),
        )
        events.seq[run_id] = last["seq"]  # continue numbering after an earlier attempt
        events.append(run_id, "metadata", {"run_id": run_id, "attempt": run["attempt"]})

        async def drive() -> None:
            async for part in graph.astream(
                graph_input,
                config,
                stream_mode=modes,
                subgraphs=bool(kw.get("stream_subgraphs")),
                durability=kw.get("durability"),
                control=me.control,
                version="v2",
            ):
                events.append(run_id, *to_event(part))

        me.task = asyncio.create_task(drive())
        if draining.is_set():
            me.control.request_drain("shutdown")
        await asyncio.wait({me.task})  # never raises; we read the outcome ourselves
        error: BaseException | None = None
        try:
            me.task.result()
            outcome = "finished"
        except asyncio.CancelledError:
            outcome = "cancelled"
        except GraphDrained:
            outcome = "drained"
        except Exception as exc:  # noqa: BLE001 - a failing graph is data, not a crash
            outcome, error = "failed", exc

        if me.fenced:  # another pod owns this run now
            events.discard(run_id)
            return
        if outcome == "drained" or (outcome == "cancelled" and me.cancel_action is None):
            await events.flush()  # shutdown: hand the run back to the queue
            await fetchall(
                """UPDATE runs SET status = 'pending', worker_id = NULL, lease_until = NULL,
                          updated_at = now()
                   WHERE run_id = %s AND worker_id = %s AND status = 'running'
                   RETURNING 1""",
                (run_id, WORKER_ID),
            )
            await notify("run_queue")
            return
        if outcome == "failed":
            status = "error"
            events.append(
                run_id, "error", {"error": type(error).__name__, "message": str(error)}
            )
        elif outcome == "cancelled":
            status = "interrupted"
            if me.cancel_action == "rollback":
                await rollback_checkpoints(thread_id, run_id)
        else:  # finished: done, or paused at an interrupt()
            status = "interrupted" if (await graph.aget_state(config)).next else "success"
        # Order matters: (1) every event is in the log, (2) the rows flip, (3) 'end' is
        # appended. A client that sees 'end' and immediately reads the thread finds its
        # final status.
        await events.flush()
        if await finish(run, status, str(error) if error else None):
            events.append(run_id, "end", {"run_id": run_id, "status": status})
            await events.flush()
    except Exception:
        log.exception(
            "run %s crashed in the executor; the lease will expire and it is retried",
            run_id,
        )
    finally:
        local.pop(run_id, None)
        events.seq.pop(run_id, None)
        hub.queue_bell.set()  # capacity freed: look at the queue again


async def thread_status(thread_id: str, assistant_id: str, failed: bool = False) -> str:
    if await fetchone(
        "SELECT 1 FROM runs WHERE thread_id = %s AND status IN ('pending','running') "
        "LIMIT 1",
        (thread_id,),
    ):
        return "busy"
    if failed:
        return "error"
    snap = await graph_for(assistant_id).aget_state(
        {"configurable": {"thread_id": thread_id}}
    )
    return "interrupted" if snap.next else "idle"


async def finish(run: dict, status: str, error: str | None) -> bool:
    done = await fetchone(  # fenced by ownership: a pod that lost the lease changes nothing
        """UPDATE runs SET status = %s, error = %s, lease_until = NULL, updated_at = now()
           WHERE run_id = %s AND worker_id = %s AND status = 'running' RETURNING run_id""",
        (status, error, run["run_id"], WORKER_ID),
    )
    if done:
        new = await thread_status(
            run["thread_id"], run["assistant_id"], failed=status == "error"
        )
        await fetchall(
            "UPDATE threads SET status = %s, updated_at = now() WHERE thread_id = %s "
            "RETURNING 1",
            (new, run["thread_id"]),
        )
        await notify("run_queue")  # an enqueued run of this thread can start now
    return done is not None


async def rollback_checkpoints(thread_id: str, run_id: str) -> None:
    # AsyncPostgresSaver has no adelete_for_runs: every checkpoint carries metadata.run_id,
    # so we delete this run's checkpoints (and their pending writes) and the thread is as
    # before.
    await fetchall(
        """WITH gone AS (
               DELETE FROM checkpoints WHERE thread_id = %s AND metadata->>'run_id' = %s
               RETURNING checkpoint_ns, checkpoint_id)
           DELETE FROM checkpoint_writes w USING gone g
           WHERE w.thread_id = %s AND w.checkpoint_ns = g.checkpoint_ns
             AND w.checkpoint_id = g.checkpoint_id
           RETURNING 1""",
        (thread_id, run_id, thread_id),
    )


def cancel_local(run_id: str, action: str = "interrupt") -> None:
    me = local.get(run_id)
    if me and me.task and not me.task.done() and me.cancel_action is None:
        me.cancel_action = action
        me.task.cancel()  # CancelledError lands inside the running node


async def close_unowned(run_id: str, status: str) -> None:
    """Write the final 'end' event for a run that no worker is executing."""
    await fetchall(
        """INSERT INTO run_events (run_id, seq, event, data)
           SELECT %s, coalesce(max(seq), 0) + 1, 'end', %s FROM run_events WHERE run_id = %s
           RETURNING 1""",
        (run_id, dumps({"run_id": run_id, "status": status}), run_id),
    )
    await notify("run_events", run_id)


async def heartbeat_loop() -> None:
    tick = 0
    while True:
        await asyncio.sleep(HEARTBEAT_S)
        tick += 1
        try:
            # renew the leases of runs that are alive HERE, and read their cancel flags
            mine = await fetchall(
                """UPDATE runs SET lease_until = now() + %s * interval '1 second'
                   WHERE worker_id = %s AND status = 'running' AND run_id = ANY(%s)
                   RETURNING run_id, cancel_requested""",
                (LEASE_S, WORKER_ID, list(local)),
            )
            for row in mine:
                if row["cancel_requested"]:  # the doorbell was missed: the row is the truth
                    cancel_local(row["run_id"], row["cancel_requested"])
            for run_id in set(local) - {row["run_id"] for row in mine}:
                me = local[run_id]
                if (
                    me.task and not me.task.done()
                ):  # we no longer own it: stop and stay silent
                    me.fenced = True
                    me.task.cancel()
            expired = (
                await fetchall(  # any pod may take over runs whose owner stopped renewing
                    """UPDATE runs
                       SET worker_id = NULL, lease_until = NULL, updated_at = now(),
                         status = CASE WHEN attempt >= %s THEN 'error' ELSE 'pending' END,
                         error = CASE WHEN attempt >= %s THEN 'worker lost' ELSE error END
                       WHERE status = 'running' AND lease_until < now()
                       RETURNING run_id, thread_id, assistant_id, status""",
                    (MAX_ATTEMPTS, MAX_ATTEMPTS),
                )
            )
            for row in expired:
                if row["status"] == "error":  # crashed its worker too often: stop retrying
                    await fetchall(
                        "UPDATE threads SET status = 'error', updated_at = now() WHERE "
                        "thread_id = %s RETURNING 1",
                        (row["thread_id"],),
                    )
                    await close_unowned(row["run_id"], "error")
            if expired:
                await notify("run_queue")
            if tick % 60 == 0:  # the log is for replay, not for history
                await fetchall(
                    """DELETE FROM run_events e USING runs r
                       WHERE e.run_id = r.run_id AND r.status NOT IN ('pending','running')
                         AND r.updated_at < now() - %s * interval '1 second' RETURNING 1""",
                    (EVENT_TTL_S,),
                )
        except Exception:
            log.exception("heartbeat failed")

def begin_drain() -> None:
    """SIGTERM: stop claiming, end SSE responses, let runs stop at the next super-step."""
    draining.set()
    hub.ring_all()
    for me in local.values():
        me.control.request_drain("shutdown")


@asynccontextmanager
async def lifespan(app: FastAPI):
    global pool
    pool = AsyncConnectionPool(
        DSN,
        min_size=2,
        max_size=int(os.environ.get("POOL_MAX", "10")),
        open=False,
        kwargs=CONN_KW,
    )
    await pool.open()
    async with (
        pool.connection() as conn
    ):  # in production: a migration job, not pod start-up
        # One pod migrates at a time. Poll with try-lock instead of blocking in
        # pg_advisory_lock(): setup() runs CREATE INDEX CONCURRENTLY, which waits for every
        # open transaction, including a session that is blocked waiting for this very lock.
        # That is a deadlock.
        while not (
            await (
                await conn.execute("SELECT pg_try_advisory_lock(727274) AS ok")
            ).fetchone()
        )["ok"]:
            await asyncio.sleep(0.2)
        try:
            await AsyncPostgresSaver(conn).setup()  # LangGraph's own tables + migrations
            for statement in SCHEMA:
                await conn.execute(statement)
        finally:
            await conn.execute("SELECT pg_advisory_unlock(727274)")
    background = [
        asyncio.create_task(job())
        for job in (hub.run, events.run, worker_loop, heartbeat_loop)
    ]

    loop = asyncio.get_running_loop()
    previous = signal.getsignal(signal.SIGTERM)  # uvicorn's handler

    def on_sigterm(signum, frame):
        loop.call_soon_threadsafe(begin_drain)  # ours first ...
        if callable(previous):
            previous(signum, frame)  # ... then uvicorn starts its own shutdown

    signal.signal(signal.SIGTERM, on_sigterm)
    yield
    begin_drain()
    tasks = [me.task for me in local.values() if me.task]
    if tasks:  # give the current super-steps time to finish
        _, late = await asyncio.wait(tasks, timeout=GRACE_S)
        for task in late:
            task.cancel()  # too slow: cancel; execute() re-queues it
    for _ in range(100):  # let execute() write its final rows
        if not local:
            break
        await asyncio.sleep(0.05)
    await events.flush()
    for task in background:
        task.cancel()
    await pool.close()


app = FastAPI(title="LangGraph on Postgres", lifespan=lifespan)

    assistant_id: str
    input: dict[str, Any] | None = None
    command: dict[str, Any] | None = (
        None  # {"resume": ...} | {"update": ...} | {"goto": ...}
    )

STREAM_MODES = {
    "values",
    "updates",
    "custom",
    "messages-tuple",
    "checkpoints",
    "tasks",
    "debug",
}

async def create_run(thread_id: str, body: RunCreate) -> dict:
    if body.assistant_id not in GRAPHS:
        raise HTTPException(404, f"unknown assistant {body.assistant_id!r}")
    modes = [body.stream_mode] if isinstance(body.stream_mode, str) else body.stream_mode
    if unknown := set(modes) - STREAM_MODES:
        raise HTTPException(422, f"unsupported stream_mode {sorted(unknown)}")
    strategy = body.multitask_strategy or "enqueue"  # the Agent Server's default
    kwargs = {
        "input": body.input,
        "command": body.command,
        "config": body.config,
        "stream_mode": modes,
        "stream_subgraphs": body.stream_subgraphs,
        "durability": body.durability,
    }
    to_cancel: list[str] = []
    async with pool.connection() as conn, conn.transaction():
        # Lock the thread row: two concurrent creates on one thread are decided one after
        # the other.
        thread = await (
            await conn.execute(
                "SELECT thread_id FROM threads WHERE thread_id = %s FOR UPDATE",
                (thread_id,),
            )
        ).fetchone()
        if thread is None:
            if body.if_not_exists != "create":
                raise HTTPException(404, f"thread {thread_id} not found")
            await conn.execute("INSERT INTO threads (thread_id) VALUES (%s)", (thread_id,))
        active = await (
            await conn.execute(
                "SELECT run_id FROM runs WHERE thread_id = %s AND status IN "
                "('pending','running')",
                (thread_id,),
            )
        ).fetchall()
        if active and strategy == "reject":
            raise HTTPException(
                409, "thread already has an active run (multitask_strategy=reject)"
            )
        if strategy in ("interrupt", "rollback"):
            to_cancel = [row["run_id"] for row in active]
        run = await (
            await conn.execute(
                """INSERT INTO runs
                     (run_id, thread_id, assistant_id, kwargs, metadata, multitask_strategy)
                   VALUES (%s, %s, %s, %s, %s, %s) RETURNING *""",
                (
                    str(uuid.uuid4()),
                    thread_id,
                    body.assistant_id,
                    Jsonb(jsonable(kwargs)),
                    Jsonb(body.metadata or {}),
                    strategy,
                ),
            )
        ).fetchone()
        await conn.execute(
            "UPDATE threads SET status = 'busy', updated_at = now(), metadata = metadata "
            "|| %s WHERE thread_id = %s",
            (Jsonb({"graph_id": body.assistant_id}), thread_id),
        )
    for run_id in to_cancel:  # the new run starts when the old one has stopped
        await request_cancel(run_id, strategy)
    await notify("run_queue")  # after commit: wake the workers on every pod
    hub.queue_bell.set()
    return run

async def request_cancel(run_id: str, action: str = "interrupt") -> dict | None:
    run = await fetchone(  # one atomic statement decides the race against a worker's claim
        """UPDATE runs SET cancel_requested = %s, updated_at = now(),
                  status = CASE WHEN status = 'pending' THEN 'interrupted' ELSE status END
           WHERE run_id = %s AND status IN ('pending','running') RETURNING *""",
        (action, run_id),
    )
    if run is None:
        return None  # already finished
    if (
        run["status"] == "interrupted"
    ):  # it never started: nobody else will close its stream
        status = await thread_status(run["thread_id"], run["assistant_id"])
        await fetchall(
            "UPDATE threads SET status = %s, updated_at = now() WHERE thread_id = %s "
            "RETURNING 1",
            (status, run["thread_id"]),
        )
        await close_unowned(run_id, "interrupted")
    else:
        await notify(
            "run_cancel", f"{action}:{run_id}"
        )  # every pod hears it; the owner acts
    return run


def stream_response(
    run: dict, after: int, on_disconnect: str | None = None
) -> StreamingResponse:
    run_id, thread_id = run["run_id"], run["thread_id"]

    async def body():
        finished = False
        try:
            async for row in tail(run_id, after):
                yield sse(row)
                finished = finished or (row is not None and row["event"] == "end")
        finally:
            # Reached on a normal end AND when the client goes away. The run is not ours to
            # stop: it lives in the worker, unless the caller asked for
            # on_disconnect=cancel.
            if not finished and on_disconnect == "cancel" and not draining.is_set():
                spawn(request_cancel(run_id))

    return StreamingResponse(
        body(),
        media_type="text/event-stream",
        headers={
            "Cache-Control": "no-store",
            "X-Accel-Buffering": "no",  # tell nginx not to buffer
            # where to reconnect (the SDK follows it)
            "Location": f"/threads/{thread_id}/runs/{run_id}/stream",
            "Content-Location": f"/threads/{thread_id}/runs/{run_id}",
        },
    )


async def wait_for_end(run: dict) -> Any:
    ended = False
    async for row in tail(run["run_id"], 0):
        ended = ended or (row is not None and row["event"] == "end")
    if not ended:  # this pod is draining: let the client ask another one
        raise HTTPException(
            503,
            "shutting down, retry",
            headers={"Location": f"/threads/{run['thread_id']}/runs/{run['run_id']}/join"},
        )
    thread = await get_thread(run["thread_id"])
    snap = await thread_graph(thread).aget_state(
        {"configurable": {"thread_id": run["thread_id"]}}
    )
    return jsonable(snap.values)

from langchain_core.outputs import ChatGeneration, ChatGenerationChunk, ChatResult
from langgraph.config import get_stream_writer

from langgraph.types import interrupt
from typing_extensions import TypedDict


class SlowFakeChat(BaseChatModel):
    """Stands in for a real LLM: emits one token every `delay` seconds."""

    text: str = "Postgres is enough: a queue, a log and a doorbell."
    delay: float = 0.05

    @property
    def _llm_type(self) -> str:
        return "slow-fake"

    def _generate(self, messages, stop=None, run_manager=None, **kwargs: Any) -> ChatResult:
        return ChatResult(
            generations=[ChatGeneration(message=AIMessage(content=self.text))]
        )

    async def _agenerate(
        self, messages, stop=None, run_manager=None, **kwargs: Any
    ) -> ChatResult:
        text = ""  # just as slow when nobody is streaming tokens
        async for chunk in self._astream(messages, stop, None, **kwargs):
            text += chunk.message.content
        return ChatResult(generations=[ChatGeneration(message=AIMessage(content=text))])

    async def _astream(self, messages, stop=None, run_manager=None, **kwargs: Any):
        for token in re.findall(r"\S+\s*", self.text):
            await asyncio.sleep(self.delay)
            chunk = ChatGenerationChunk(message=AIMessageChunk(content=token))
            if run_manager:
                await run_manager.on_llm_new_token(token, chunk=chunk)
            yield chunk

async def plan(state: AgentState):

    write({"stage": "planning"})
    await asyncio.sleep(0.05)

        decision = interrupt({"question": "Run the answer step?", "plan": state["plan"]})

            return {"messages": [AIMessage(content="Cancelled by reviewer.")]}
    return {}

            raise RuntimeError(f"node {name} failed")
